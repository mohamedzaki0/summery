٣. الواجهة الأمامية من جوّه

ملف ج بيفتح الطبقة الأولى (الأمامية) ويوريك إنها تلات تقنيات. والمتصفح هو اللي بيشغّلها على جهازك، يعني هي نفس العميل بتاع ملف ب.

HTML · البنية

العناوين والفقرات والصور والروابط. (هيكل المبنى)

CSS · المظهر

الألوان والتخطيط والخطوط. (الديكور)

JavaScript · السلوك

بتفعّل الاستجابة للضغط وبتحدّث جزء فقط من الشاشة. (الكهرباء والسباكة)

  • HTML الدلالي (header, nav, main, footer) بيساعد قارئ الشاشة، ومش بيضمن ترتيبًا أعلى في البحث.
  • التصميم المتجاوب: ليه مهم؟ لأن العميل ممكن يكون كمبيوتر أو موبايل أو تابلت ب، فالتخطيط لازم يتأقلم.
  • React وVue وNext.js: مكتبات وأطر بتوفر مكونات جاهزة. وNext.js بيعرض الصفحات على الخادم والعميل، يعني بيقف على الحدود بين الأمامية والخلفية.

الخطوة اللي بعد كده: الأمامية دي بتتكلم مع الخادم إزاي؟ كمّل لقسم الاتصال ←

٤. الطريق بين الأمامية والخلفية

العميل (الأمامية) يطلب، والخادم (الخلفية) يرد، بقواعد منظمة:

المفهوممعناهبيخدم مين؟
HTTPقواعد تبادل الرسائل بين المتصفح والخادمأمامية ↔ خلفية
HTTPS = HTTP + TLSنفس القواعد في اتصال محمي: سرية، واكتشاف تلاعب، ومصادقة الخادمنفس الطريق
GET / POSTGET "هات لي"، وPOST "خد دي وعالجها"الطلب من الأمامية
رمز الحالة 200 / 404 / 500نجاح / مورد غير موجود / عطل داخلي في الخادمالرد من الخلفية
APIالباب المنظم اللي الأمامية بتطلب منه من الخلفيةالنادل في التشبيه
JSONصيغة نصية منظمة (كائنات ومصفوفات وقيم بسيطة) بترجع بيها البياناتالرد، والـ JavaScript بتقراه ج

مثال طلب ورد:

مراجعة موحدة

  • ثلاث طبقات: أمامية (العميل، مبنية بـ HTML/CSS/JS)، خلفية (الخادم)، بيانات.
  • الأمامية تطلب بـ HTTP/HTTPS وبطريقة GET أو POST، والخلفية ترد برمز حالة وغالبًا JSON عبر API.
  • الأمامية لا تصل للبيانات مباشرة، دايمًا عن طريق الخلفية.
